# /lesson — материалы урока → карточки

Ты генерируешь карточки для личного приложения Drill: EN (подсказки на русском) и SK (подсказки на украинском). Пользователь проходит их на телефоне перед сном.

## Шаг 0. Прочитай справку

Всегда: `references/learner.md` (кто учится и какой нужен стиль) и `references/cards.md` (формат и типы карточек — приложение умеет только это). Затем по языку: `references/en.md` или `references/sk.md`.

## Шаг 1. Пойми, что просят

| Режим | Когда | Что делать |
|---|---|---|
| **Новый урок** | Скинуты скриншоты или материалы | Новая папка `lesson-NN` |
| **Дополнить** | «добавь к lesson-03», «ещё карточек на теги» | Дописать карточки в существующий урок, продолжив нумерацию id |
| **Добить правило** | «путаю does и is», «добей правило X» | 5–8 карточек на контраст: пары фраз, где отличается только целевой элемент |
| **Из жизни** | «сказал X, поправили на Y», «не смог сказать Z» | Колода `life` (см. язык), `spot` + `translate`/`chunk` |

Язык определи по материалам: словацкая диакритика (*á ä č ď ľ ň ô ŕ š ť ž*) и словацкие слова → `sk`; английский → `en`. Аргумент `en`/`sk` в вызове главнее. Если материалы смешанные или непонятные — спроси одним вопросом.

## Шаг 2. Посмотри, что уже есть

Прочитай `content/<lang>/lessons/*/lesson.json` (и `source.md` при необходимости). Отсюда:

- следующий номер урока (`lesson-NN`, `number: NN`);
- пройденные правила и лексика — в дриллах можно использовать только их и слова текущего урока;
- существующие id и фразы, чтобы не дублировать.

## Шаг 3. Расшифруй материалы → `source.md`

Скриншоты в репозиторий не попадают, поэтому расшифровка — единственная копия урока. Запиши `content/<lang>/lessons/<id>/source.md`:

```markdown
# <тема> — <дата>
## Правила
(дословно, с примерами со слайда)
## Слова
## Тексты / упражнения
## Комментарий
(что сказал пользователь: «учитель просил обратить внимание на…»)
```

- Диакритику и написание сохраняй точно.
- Неразборчивое помечай `[неразборчиво]` и спрашивай. Не додумывай.
- Упражнения из учебника — тоже материал: из них берутся тема и примеры.

## Шаг 4. Карта правил

Разложи урок на правила по `cards.md`: формула в 2–4 строки, 1–3 примера. Сложное делим на подправила, исключения — отдельными правилами. Лексику без правила — в `chunk`.

## Шаг 5. Карточки

- 25–40 на урок, 6–12 на правило, пропорции типов — из справки по языку.
- Сначала примеры со слайда как есть (`from-slide`), потом новые фразы, меняя по одному параметру: подлежащее, время, полярность, глагол.
- 2–3 карточки на правило в жизненном контексте (`work` для EN, `life` для SK).
- Если правило задевает зону, где мешает русский или украинский, добавь 2–3 `choice`/`spot` именно под эту ошибку.
- Стиль — строго по `learner.md`: коротко, просто, зубрибельно.

## Шаг 6. Запиши и провалидируй

Запиши `lesson.json` и запусти:

```bash
npm run validate
```

Исправь все ошибки. Предупреждения (длинный ответ, дубль) исправь, если это не осознанное решение.

## Шаг 7. Ревью

Пройди каждую карточку по чеклисту из `cards.md` и исправь найденное. Затем оцени урок целиком как преподаватель:

- хватает ли вариантов на каждое правило, чтобы оно стало автоматическим (а не одна фраза, выученная наизусть);
- есть ли контраст с типичной ошибкой;
- не слишком ли тяжело: длинные фразы, незнакомые слова, две трудности в одной карточке.

Для SK дополнительно: сверка форм по `sk.md`, сомнительные — `"verified": false`.

## Шаг 8. Отчёт

Коротко, без пересказа всех карточек:

```
Урок 07 · Question tags (EN) — 5 правил, 34 карточки
translate 16 · transform 5 · choice 6 · spot 2 · chunk 5 · 9 со слайдов

Усвоение: теги с be и do — хватает. aren't I — всего 3 карточки,
стоит добить после пары прогонов. Самое трудное — теги с have (путается с do).

Не разобрал: нижняя часть второго скриншота.
На проверку учителю (скрыты): 2 формы.

Коммитим и деплоим?
```

Если в языке есть только колода `demo`, а это первый настоящий урок — предложи удалить `demo`.

## Шаг 9. Коммит и деплой — только после «да»

```bash
git add content/<lang>/lessons/<id>
git commit -m "content(<lang>): <id> — <title>"
git push
```

После пуша GitHub Actions соберёт и задеплоит приложение за 1–2 минуты. Если у репозитория нет remote или пуш не прошёл — скажи об этом, ничего не выдумывай.
